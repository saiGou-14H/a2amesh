## 1. 目的、口径与使用方式

本文把权威实施计划中的未完成工作整理为可执行工作包（Work Package, **WP**）、依赖、验收证据、风险和建议节奏。它不是进度百分比重算，也不以代码文件数、测试数或历史候选数量替代阶段验收。

### 1.1 三种状态必须分开

| 维度 | 当前结论 | 含义 |
|---|---|---|
| 工程建设进度 | 约 24%（历史账本口径） | 已有局部实现、合同和验证资产；不等于阶段完成。 |
| 阶段 exit gate | 0 个 C0～C8 整阶段已证实闭环 | 一个阶段只有在本阶段退出条件、精确树门禁、独立复审和所需外部证据都闭合后才算完成。 |
| 发布/生产就绪 | 0% | 无目标剖面的 C7/C8、官方黑盒、真机故障注入、签名证据与批准。 |

### 1.2 本排期的硬规则

1. **失败关闭（fail-closed）**：独立复审没有正常结束且明确给出 `VERDICT=PASS`，一律为 `INCONCLUSIVE`，不能推进为交付通过。
2. **精确树绑定**：每个候选都记录 commit 与 tree；复审期间不改被审树。修复后重新门禁、重新复审。
3. **先 RED 后 GREEN**：行为变化先有可复现失败测试，再作最小实现；测试、文档、schema 同一可回滚提交。
4. **本地不替代托管/真机**：disposable Redis/NATS replay 只能证明本地路径；不能替代 GitHub-hosted Actions、官方 SDK 黑盒或 Windows 真机。
5. **不越级宣传**：合同、原型或局部 test 不能称“官方兼容”“阶段完成”或“生产可用”。
6. **安全前置**：任何未关闭的设计 P0/P1、共享幂等/lease/outbox 原子性、身份边界或 release evidence 问题，阻断对应能力的公开宣传。

### 1.3 资源与日历假设

本仓库未给出稳定团队容量、可投入全职人周、Windows 环境可用窗口、生产域或外部 OAuth/WORM/Object Store 资源。因此本文先给出**依赖驱动的波次（Wave）**，不把它伪装为承诺日期。

为帮助排期，附录给出一个**单一全职实现者、每周 5 个有效工程日、无重大返工、外部环境按需可用**的顺序估算。它是规划锚点，不是交付承诺；任何新 P0/P1、缺环境、设计变更或 hosted CI 阻断都会顺延。

### 4.1 不可并行的边界

1. **GOV-01 / GOV-02 / GOV-05 是首要关键路径**：ADR-040、C2 实现、C3/C4 不能以未冻结设计或未闭合 CI 候选作为“已验证基础”。
2. **C2 是主数据正确性路径**：C2.5/C3/C4/C5 都依赖真实 State，而不是纯 contracts 或内存字典。
3. **C3 的 dispatch/outbox/ACL/stream session 依赖 C2/C2.5 写事实**：不可先用 NATS publish 代替 durable intent/outbox。
4. **C5 只可在 C1～C4 基础行为可证后实现**：Gateway 不能另造状态、鉴权或流式语义。
5. **C5 是 C6-I 与 C6-E 的共同实现前置**：C6-E 仅可在 C5 contract 稳定后、且另有隔离人力时与 C6-I 并行开发；它不能绕过 C5，也不能跳过 C6-I/C7/C8 宣称 EXTENDED。公开剖面严格累积：`EXTENDED ⊃ INTEROP ⊃ CORE`。

### 4.2 可并行但需隔离的边界

| 并行泳道 | 可从何时开始 | 约束 |
|---|---|---|
| G0 final review / M9c CI remediation | 立即 | 分别在独立 worktree；最终由 GOV-05 整合。 |

## 6. 每个工作包的统一交付模板

每个 WP 必须保留以下证据，缺任何一个不能将状态改为“完成”：

1. **范围冻结**：需求/设计引用、非目标、输入基线 commit/tree。
2. **RED**：测试先失败的命令与真实输出；若纯文档/infra 包不适用，说明替代负向验证。
3. **GREEN**：最小实现、targeted tests、lint/format、`git diff --check`。
4. **checkpoint**：小而可回滚的 local commit，提交后 clean tree，记录 commit/tree。
5. **全量或定义范围门禁**：命令、统计、环境、skip 原因；已知基线债务与新增失败明确隔离。
6. **独立复审**：精确 tree、正常结束、明确 `VERDICT=PASS`；任何 timeout/provider block/max iteration/无 verdict = `INCONCLUSIVE`。
7. **远端闭环**：push、remote SHA 回读、hosted CI exact SHA；若阶段需要，附官方 SDK/真机/故障注入报告。
8. **文档同步**：计划、ADR、README、当前/目标状态、风险/Runbook 一并更新；不得提前宣传能力。

### 6.1 发现问题后的返工规则

```text
候选树 → 门禁 → 独立审阅
                     │
          PASS ──────┼──> push/hosted CI/下一 WP
          FAIL       │
          INCONCLUSIVE
                     ↓
       新 worktree 修复 → 新 commit/tree → 全新门禁/复审
```

不得在被审树上静默修复后沿用旧 review；不得用“局部绿”抵消未关闭的 fail-closed 结论。
