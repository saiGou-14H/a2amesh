### 1.3 Git 2.34 路径修复方案验证

在 disposable 临时 Git 仓库验证了当前 Git 版本的实际行为：

1. 对 dirty linked worktree 执行 `git worktree move --force` 后，其 HEAD、工作区修改及 WIP 文件 SHA-256 均保持不变；
2. `git worktree move` 会更新主仓 `.git/worktrees/<id>/gitdir` 指向新的 linked worktree `.git`；
3. 主仓不能用 `git worktree move` 迁移。因此在已验证的布局下，主仓以原子 `rename` 移动后，将每个 linked worktree 的 `.git` 文件中旧主仓 admin 路径替换为新主仓的同一 admin 路径；
4. 在临时仓中回读 `git worktree list`、`rev-parse --git-common-dir`、HEAD、dirty status 和 WIP SHA-256，均通过。

这不是 `git worktree repair` 的替代性猜测，而是针对已安装 Git `2.34.1`、当前无 submodule/lock 的实际布局验证；迁移后还进行了项目树的完整回读验证。
